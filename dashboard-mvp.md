# Dashboard MVP para clientes WEP

Documento base para una version simple del dashboard de clientes del Web Evolution Program.

## Objetivo

El dashboard debe responder de forma simple a estas preguntas:

- Que estamos haciendo
- Por que lo estamos haciendo
- Que impacto esta teniendo
- Que necesita el cliente validar

## Estructura simple recomendada

### 1. Resumen

Mostrar una vista rapida del estado del servicio:

- Estado del mes: `En marcha`, `Pendiente de validacion` o `Completado`
- Horas usadas vs horas disponibles
- Numero de tareas completadas
- Proxima accion recomendada

### 2. Prioridades del mes

Lista de tareas ordenadas por prioridad.

Cada tarea deberia mostrar:

- Titulo
- Prioridad
- Impacto esperado
- Estado
- Si requiere validacion del cliente

Ejemplos:

- Mejorar estructura de pagina de servicios
- Simplificar formulario de contacto
- Optimizar velocidad en mobile

### 3. Progreso

Visualizar el estado operativo del trabajo:

- Pendiente
- En curso
- Completado
- Bloqueado

Puede representarse como lista simple o como tablero tipo kanban.

### 4. Impacto

Limitar esta seccion a 3 o 4 metricas maximo.

Metricas recomendadas:

- Conversiones
- Velocidad de carga
- Leads generados
- Interaccion con CTAs

Debajo conviene añadir dos bloques cortos:

- Que hemos mejorado este mes
- Que esperamos mejorar el siguiente

### 5. Pendiente del cliente

Seccion dedicada a validaciones y bloqueos.

Mostrar:

- Tareas esperando feedback
- Materiales pendientes del cliente
- Decisiones que hay que confirmar

### 6. Historial mensual

Un registro simple por mes:

- Mes actual o meses anteriores
- Tareas realizadas
- Resultado principal
- Siguiente foco

## Version MVP realista

Si hubiese que construir una primera version funcional sin complicarla, esta seria la estructura minima:

- Cabecera con nombre del proyecto, estado y horas
- Bloque `Prioridades del mes`
- Bloque `Tareas en curso`
- Bloque `Resultados`
- Bloque `Pendiente del cliente`

## Criterios de producto

El dashboard no debe llenarse de metricas por llenar. Si el cliente entra y no sabe que mirar, falla.

Prioridades:

- 5 a 7 KPIs como maximo
- Backlog priorizado
- Estado del mes
- Impacto visible
- Decisiones pendientes

## Enfoque alineado con el WEP

Como el WEP no se vende como un servicio SEO integral, el dashboard debe hablar de:

- Estructura web
- Conversion
- Rendimiento
- UX
- Analitica
- Visibilidad organica cuando aplique

Evitar presentarlo como una plataforma de gestion de contenidos o una herramienta de reporting SEO puro.
